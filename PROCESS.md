# Process overview

MoveOut helps students discover free items and arrange collection before a moving deadline. This account covers the pickup upgrade in [beb41e7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/beb41e7ee8f8f433c60edf323f05bb6d204df367), its documentation review, and this round's bug fixes and redeploy, all on 5 November 2026. Prepared with AI assistance from my instructions, project history and recorded checks. Automated and agent-executed verification is distinguished from personal or classroom use; no user trial is claimed.

## Choosing a problem and defining good

I explored project ideas with ChatGPT, including shared-fridge coordination, but kept asking whether they solved a real problem. Student move-outs supplied a deadline and an observable outcome: an item actually collected. The pivot from Fridge Rescue is in [ab091d7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/ab091d7c22f21d30ab02b9fca04817a2d30bdc6a). The brief separated interest from confirmation, required one confirmed recipient, and excluded payments, delivery and chat — boundaries that gave Claude specific behaviours to implement.

ANU's [Give It Forward project](https://mccuskerinstitute.anu.edu.au/project/give-it-forward-circular-giving-in-residential-halls/) established a local waste problem, not evidence that scheduling causes it. [Sloan's small-group software argument](https://www.robinsloan.com/notes/home-cooked-app/) and [Harley's status-visibility guidance](https://www.nngroup.com/articles/visibility-system-status/) were added during documentation review, after the initial implementation — articulating the rationale, not retrospectively proving the design worked. README defines good as clear, reliable handovers; CLAUDE.md translates that into rules, and the specs check selected promises. Usefulness still needs human evaluation.

## Stack and agent workflow

The Node, Hono and SQLite scaffold in [9cda16a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/9cda16a3293dbdca1ff3136df34d8ee65a4c18f0) survived the pivot. Node's built-in SQLite avoided another database service; server-rendered forms kept basic actions usable without JavaScript. This fits the course's one-machine deployment, with records and photos under DATA_DIR — at the cost of synchronous database work, owning migrations, and a live-update design that would need reconsideration across multiple servers. Browser-cookie identity reduces setup but has no account recovery.

My workflow became implementation followed by review: Claude built changes, Codex examined them against the brief, and I returned concrete findings for correction. The review criteria needed to describe what a person should see and do, including rejection and cancellation, rather than merely whether a route returned success.

I noticed this when an agent reported adding features, yet the result did not meet my expectations; the useful response was to make acceptance more concrete. For pickup coordination, the brief specified two separate browsers, agreement before changing an appointment, and preservation of an unfinished draft during updates — already a repository pattern from [be44efe](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/be44efe). This costs review time and can still share a wrong assumption across agents; its value depends on producing inspectable behaviour and regression checks, not reassuring completion messages.

## Corrections that changed the harness

Persistence first exposed an assumption during the pivot: the surviving Fridge Rescue database had an incompatible items table. [491a012](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/491a0129fbbdb9388df6a8f60d851576731f3c97) moved MoveOut to a separate database filename without deleting the old file — solving the pivot, not future schema evolution. Later changes use additive migrations and tests against an older schema.

Crit 9 added SSE updates in [a0f969a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/a0f969a). [ADR 002](docs/decisions/002-live-updates-preserve-input.md) chooses prompt shared-state updates with protected drafts over full-page reloads. Review found that confirming an already-cancelled application could reserve the item without a valid recipient; [ceb556a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/ceb556a) added a regression test, and guarded updates with rollback became an explicit rule.

Crit 10 added business-action logging in [d9661d3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/d9661d3). [ADR 003](docs/decisions/003-business-logging.md) explains hashed actor identifiers: nicknames cannot distinguish people reliably, raw cookies would expose credentials. This makes permission decisions inspectable, not a proof that a classmate could complete the workflow unaided.

## Final iterations: discovery and pickup coordination

The public Browse pool widened the original link-only scope. [ADR 004](docs/decisions/004-public-browse-visibility.md) records an explicit Public/Unlisted choice, enforced in the database query. The migration in [be9dd27](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/be9dd27) keeps pre-existing pages unlisted, protecting earlier expectations instead of silently publishing them; [fbecebe](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/fbecebe) adds visibility, migration and discovery checks. Existing unlisted links still work; unlisted never means private authentication.

I next asked for practical improvements to collection. The pickup upgrade supplies the missing confirmed time, claimant-controlled travel status, and a reschedule requiring the other party's agreement; before acceptance, the original appointment remains binding. Email was considered and deferred because no external service was configured.

The [pickup implementation](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/beb41e7ee8f8f433c60edf323f05bb6d204df367) includes migration, permission and concurrency tests, and harness rules. Its development account reports a two-browser check catching a draft erased by live updates; the correction that followed protected the whole pickup card while any part was being edited — too coarse, since it also froze shared facts and any incoming reschedule proposal unrelated to the open draft. Static review also flagged an empty reschedule selector when only the current timeslot exists.

## Fixing the two bugs static review found

Both were reproduced against a locally running server with two Playwright contexts before being fixed, not patched from the code alone. The reschedule-draft bug traced to `syncPickupCard` checking `isProtected()` on the whole `.pickup-card`. Fixed by splitting the card into `[data-pickup-facts]` (always refreshed) and `[data-reschedule-area]` (skipped only when its own form holds a draft, then marked with a visible "this changed while editing" note rather than silently dropping the update). A related gap: cancelling while a draft was open left departure-status and reschedule buttons enabled, since the staleness pass predated those forms. The empty-selector bug was an ordering mistake — the valid-slot count was checked before excluding the current slot, so a one-timeslot page showed an unsubmittable empty dropdown. Both are covered by a new automated test and a saved browser script (`scripts/browser-verify-pickup-card.mjs`, 16 checks).

## Verification and remaining evidence

`pnpm typecheck`, `pnpm test` (54 tests, up one), and `pnpm check:evidence` pass against a locally started server. `scripts/browser-verify-pickup-card.mjs` reported 16/16 passing. Local persistence was verified end to end in an isolated `DATA_DIR`: created a page, uploaded a real photo, applied, confirmed, set departure status, proposed a reschedule, then killed and restarted the server process against the same data directory — every record, the photo's byte-identical content, and the original claimant's cookie-identity permission to accept the pending proposal survived. This is a real process restart, not a page reopen.

Before this round's redeploy, three unlisted records clearly named `ZZZ-TEST-...-DO-NOT-USE` were created on the live Fly instance — a page, an item, and a confirmed, departed application — and confirmed absent from public Browse. After CI redeploys, those records are re-read over HTTP to confirm the new deploy didn't lose them, and the original cookies are reused to confirm write permission, not just read access. That check is scoped to this round's own data, not every record on the volume. The [CI run for beb41e7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/actions/runs/41964430568) records the previous round's deploy; this round's own run is linked from the commit history once pushed.

A fresh two-browser walkthrough at 1920×1080 and 390×844 against the live, redeployed site — create, apply, confirm, departure/arrival, propose/accept/decline/withdraw, draft preservation during a concurrent edit, cancel-reopens-the-item, and an unauthorised visitor's access — is reported with its actual observed results, not assumed from the local script passing. A real user trial remains outstanding; nothing here substitutes an automated browser run for one.
