# Process overview

MoveOut helps students discover free items and arrange collection before a moving deadline. This account covers the project through the pickup upgrade in [beb41e7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/beb41e7ee8f8f433c60edf323f05bb6d204df367) and the documentation review on 5 November 2026. It was prepared with AI assistance from my instructions, project history and recorded checks. Automated and agent-reported verification is distinguished from personal or classroom use; no documented user trial is claimed.

## Choosing a problem and defining good

I explored project ideas with ChatGPT, including shared-fridge coordination, but kept asking whether they solved a real problem. Student move-outs supplied a deadline and an observable outcome: an item actually collected. The pivot from Fridge Rescue is visible in [ab091d7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/ab091d7c22f21d30ab02b9fca04817a2d30bdc6a). The brief developed with ChatGPT separated interest from confirmation, required one confirmed recipient, and excluded payments, delivery and chat. These boundaries gave Claude specific behaviours to implement.

ANU's [Give It Forward project](https://mccuskerinstitute.anu.edu.au/project/give-it-forward-circular-giving-in-residential-halls/) established a local waste problem, not evidence that scheduling causes it. [Sloan's small-group software argument](https://www.robinsloan.com/notes/home-cooked-app/) and [Harley's status-visibility guidance](https://www.nngroup.com/articles/visibility-system-status/) were added during documentation review, after the initial implementation. They helped articulate the rationale rather than retrospectively prove the design worked. README now defines good as clear, reliable handovers; CLAUDE.md translates that into rules, and the specs check selected promises. Usefulness still needs human evaluation.

## Stack and agent workflow

The Node, Hono and SQLite scaffold in [9cda16a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/9cda16a3293dbdca1ff3136df34d8ee65a4c18f0) survived the pivot. Node's built-in SQLite avoided another database service; server-rendered forms kept basic actions usable without JavaScript. This fits the course's one-machine deployment, with records and photos under DATA_DIR. The costs are synchronous database work, responsibility for migrations, and a live-update design that would need reconsideration across multiple servers. Browser-cookie identity reduces setup but provides no account recovery.

My workflow became implementation followed by review: Claude built changes, Codex examined them against the brief, and I returned concrete findings for correction. A second agent was useful for challenging an implementation, but its agreement was not a substitute for executing checks. The review criteria needed to describe what a person should see and do, including rejection and cancellation, rather than merely whether a route returned success.

I noticed this distinction when an agent reported adding features and images, yet the result did not meet my expectations. The useful response was to make acceptance more concrete. For pickup coordination, the later brief specified two separate browsers, agreement before changing an appointment, and preservation of an unfinished reason during updates. The browser-verification approach already had a repository record in [be44efe](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/be44efe). This workflow costs additional review time and can still share an incorrect assumption across agents. Its value depends on producing inspectable behaviour and regression checks, rather than collecting reassuring completion messages.

## Corrections that changed the harness

Persistence first exposed an assumption during the pivot: the surviving Fridge Rescue database had an incompatible items table. [491a012](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/491a0129fbbdb9388df6a8f60d851576731f3c97) moved MoveOut to a separate database filename without deleting the old file. That solved the pivot, not future schema evolution. Later changes use additive migrations and tests against an older schema.

Crit 9 added SSE updates in [a0f969a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/a0f969a). [ADR 002](docs/decisions/002-live-updates-preserve-input.md) chooses prompt shared-state updates with protected drafts over full-page reloads or delaying the whole page. Its cost is more demanding browser reconciliation. Review found that confirming an already-cancelled application could reserve the item without a valid recipient. [ceb556a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/ceb556a) added a regression test and SSE checks; guarded updates and rollback became explicit rules. Browser scripts additionally test focus and draft preservation. Their synthetic composition events do not establish behaviour with a real operating-system input method.

Crit 10 added business-action logging in [d9661d3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/d9661d3). [ADR 003](docs/decisions/003-business-logging.md) explains hashed actor identifiers: nicknames cannot distinguish people reliably, while raw cookies would expose credentials. Logs record actions and outcomes without private free text. This makes permission decisions inspectable, but does not itself prove a classmate could complete the workflow without help.

## Final iterations: discovery and pickup coordination

The public Browse pool widened the original link-only scope. [ADR 004](docs/decisions/004-public-browse-visibility.md) records an explicit Public/Unlisted choice, enforced in the database query. The migration in [be9dd27](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/be9dd27) keeps pre-existing pages unlisted. That protects earlier expectations instead of silently publishing them. [fbecebe](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/fbecebe) adds visibility, migration and discovery checks. Existing unlisted links still work; unlisted never means private authentication.

I next asked for practical improvements to collection. The pickup upgrade supplies the missing confirmed time, claimant-controlled travel status, and a reschedule requiring the other party's agreement. Before acceptance, the original appointment remains binding. Email was considered and deferred because no external service was configured. These choices address coordination while retaining the existing reservation lifecycle.

The [pickup implementation](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/commit/beb41e7ee8f8f433c60edf323f05bb6d204df367) includes migration, permission and concurrency tests, and harness rules. Its development account reports a two-browser check catching a draft erased by live updates. The subsequent correction protects the pickup card while editing. Later static review identified the cost of that coarse protection: shared facts can also stop updating. It also identified an empty selector when only the current timeslot exists. These remain findings to reproduce and fix, not completed corrections.

## Verification and remaining evidence

The [CI run for beb41e7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-tavewang/actions/runs/41964430568) passed typechecking, all 53 tests, evidence checking and deployment. On 5 November, read-only checks returned HTTP 200 for the deployed homepage, README and live-update script; the latter two contained the pickup upgrade. This establishes deployment and availability, not a complete production walkthrough. The previous statement that this version was not deployed is superseded.

The implementation account reports local two-context browser checks at 1920×1080 and 390×844. Its reopening check demonstrates fresh retrieval, not survival across a server restart. Migration tests verify legacy records and repeated migration execution, but do not cover all records and photos across Fly redeployment. A reproducible production persistence check, a fresh two-browser walkthrough including editing conflicts, and a real user trial remain outstanding. The documentation review preserves those limits instead of treating green CI as complete acceptance. Research-note claims are evaluated separately against literature, not inferred from this project's success.
